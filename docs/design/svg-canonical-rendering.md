# 設計: SVG を描画の正本にする

- 作成日: 2026-11-08
- 状態: 手順 1（resvg の組み込み）・手順 2（見た目をそろえる）・手順 3（PNG・PDF の切り替え）済み
- 前提: 使用者は作者 1 人のため、保存ファイルの見た目や出力の互換は守らなくてよい

## 1. 目的

今は同じ虹彩を 2 つの実装で描いている。

| 用途 | 今の描画 |
|---|---|
| デスクトップ版の画面プレビュー（ペア・分割比較・A4 シート） | `WpfIrisRenderer`（WPF の DrawingContext） |
| PNG 出力 / A4 PDF（1200 DPI の画像を埋め込み） | `WpfIrisRenderer` → `RenderTargetBitmap` |
| SVG 出力 / ブラウザ版のプレビュー | `SvgExporter`（Core） |

これを **`SvgExporter` が作る SVG だけを正本**にし、画面・PNG・PDF はその SVG をラスタライズしたものにする。目的は次の 2 つ。

1. **SVG でしかできない表現を使えるようにする**。フィルター（`feTurbulence`・`feGaussianBlur`・`feDisplacementMap`・`feSpecularLighting` など）、`mix-blend-mode`、`<mask>`、グラデーションの焦点など。WPF では描けないので、今は使えない。
2. **描画の実装を 1 本にする**。今は 2 本の実装の間で見た目がずれている（4 章）。新しい表現を足すたびに両方を書く必要もなくなる。

## 2. 試作の結果（2026-11-08）

resvg 0.49.0 のコマンドライン版で、25 種のプリセットを 1 片目 10mm・1200 DPI（567×567 ピクセル）で描いて比べた。

| 比較 | 平均の差（0〜255） | 差が 8 を超える画素 |
|---|---|---|
| resvg と Edge（同じ SVG） | 0.45 | 約 0.8%（図形の縁のアンチエイリアスだけ） |
| resvg と 今の WPF 描画 | 4.5 | 約 19%（4 章の違いによるもの） |
| `feTurbulence` を使った SVG の resvg と Edge | 2.0 | 約 15%（ノイズの出方が少し違う） |

- 速さ（起動の約 90ms を除く）: 今の SVG で 1 片目 5〜170ms。WPF は 20〜90ms。繊維ノイズを足すと 1 枚あたり約 +140ms。
- 放射グラデの焦点、`feTurbulence` と `mask` と `overlay` を組み合わせた繊維ノイズ、`screen` ブレンドのオーロラは、resvg で意図どおりに描けた。

### 2.1 resvg.dll を組み込んだ後の計測（手順 1、2026-11-08）

アプリと同じプロセスで呼んだ値。9 回の中央値。

| 描画 | 時間 |
|---|---|
| ペアのプレビュー（倍率 360%）、画面の倍率 100% / 150% / 200% | 中央値 11 / 17 / 24 ms（150% で 613×327 ピクセル） |
| 同上、「特殊: オーロラ」 | 187 / 267 / 379 ms（下記の理由） |
| 片目 1200 DPI（567 ピクセル） | 24 ms（WPF は 19 ms） |
| 片目に繊維ノイズ（`feTurbulence`）を足したとき | プレビュー（204 ピクセル）29 ms、1200 DPI 166 ms |
| ペアの SVG を作る時間 | 1〜9 ms |

- ほとんどのプリセットは、ドラッグ中に描き直しても十分に速い。
- **「オーロラ」が遅い理由**: 放射ラインを円周グラデ（`<pattern>`）で塗っている。この塗りを数百本のライン 1 本ずつに使っているため、resvg がパターンを毎回描き直している。ラインを白いマスクにして、パターンで塗った四角形を 1 回だけ描く形にすると、片目 1200 DPI で約 270ms が約 70ms になった（試作で確認）。手順 2 で、放射ライン・ラメ・フレネルリングをこの形に直した。オーロラのプレビューは画面の倍率 100 / 150 / 200% で 20 / 48 / 48 ms になった。Edge との差は平均 0.43 で、ブラウザ版でも同じに見える。
- 繊維ノイズはプレビューで約 30ms かかる。ドラッグ中だけ解像度を下げる対策（6 章）は、手順 7 で実際に使うときに決める。

## 3. 全体の構成

```
IrisParameters
   │
   ▼
SvgExporter (Core)  ──────────────►  SVG 出力 / ブラウザ版プレビュー（ブラウザが描画）
   │  SVG 文字列
   ▼
ResvgRasterizer (デスクトップ版, P/Invoke → resvg.dll)
   │  BGRA の画素
   ├─► 画面プレビュー（WriteableBitmap を DrawingContext に描く）
   ├─► PNG 出力
   └─► A4 PDF（片目ずつ 1200 DPI の画像として埋め込む）
```

WPF に残すのは、虹彩の外側のものだけにする。用紙・余白線・ページ番号・警告の文字・ラベル・背景の格子・色見本など。

### 3.1 resvg の組み込み

- **使うもの**: resvg の C API（`crates/c-api`）をビルドした `resvg.dll`（win-x64）。公式リリースにはコマンドライン版しかないため、自前でビルドする。
- **入手方法**: GitHub Actions のワークフロー `build-resvg.yml`（手動実行、またはこのファイルを変えて push したときに動く）。windows-latest の上で、タグを固定して `cargo build --release -p resvg-capi` を実行する。できた DLL は次の場所にコミットする。手元に Rust を入れなくて済む。
  - `third_party/resvg/win-x64/resvg.dll`
  - `third_party/resvg/LICENSE-*`（resvg のライセンスは Apache-2.0 / MIT。`NOTICE.md` に追記する）
  - `third_party/resvg/VERSION.txt`（タグ・コミット・DLL の SHA-256）
  - `third_party/resvg/DEPENDENCIES.txt`（DLL に入るクレートとライセンスの一覧。リリースの zip にも入れる）
- **配布**: アプリの csproj で `resvg.dll` を出力先へコピーする。リリースは今の `PublishSingleFile` と `IncludeNativeLibrariesForSelfExtract` で exe に同梱する。テストのプロジェクトはアプリを参照しているので、同じ DLL が届く。
- **ラッパー** `DollIrisGenerator/Services/ResvgRasterizer.cs`:
  - 呼ぶ関数: `resvg_options_create`、`resvg_parse_tree_from_data`、`resvg_render`（変換行列で mm → ピクセルの拡大と平行移動を渡す）、`resvg_tree_destroy`、`resvg_options_destroy`
  - `Rasterize(string svg, int widthPx, int heightPx, Matrix viewToPixel, Color? background)` が `BitmapSource` を返す（Pbgra32、凍結済み）。resvg が返すのは乗算済みの RGBA なので、R と B を入れ替えるだけで済む。
  - **UI スレッドの外から呼べる**。`RenderTargetBitmap` と違って STA が要らないので、プレビューは裏で描き、PDF は片目ずつ並列に描ける。
  - DLL を読み込めないとき（ファイルの破損など）は、起動時にメッセージを出す。代わりの描画は用意しない。
- 文字は SVG に入れない（ラベルは WPF で描く）。そのためフォントの読み込み（`resvg_options_load_system_fonts`）は使わない。

### 3.2 SvgExporter の変更

- 片目の SVG に **余白を引数で渡せる**ようにする（今は 2mm 固定。PDF の埋め込みは 1mm）。試作では viewBox を書き換えて合わせたが、本番では引数にする。
- 印刷ガイド（カットライン・中心マーク）は、今の `includePrintGuides` で SVG に含める。画面の「カットライン表示」もこれを使う。
- 1 つの SVG に「編集用」と「描画用」の区別は作らない。フィルターを使う SVG は、Illustrator などで開くと一部がラスター化される。17 章（SVG 出力）にそう書いておく。必要になったら、フィルターを省く「編集用」オプションを後で足す。

## 4. 切り替える前に揃える見た目の違い

試作の差の画像と、2 つの実装のコードを読み比べて見つけた違い。互換は気にしなくてよいので、**どちらの見た目に揃えるかを項目ごとに決め、SVG 側を直す**。

| 項目 | WPF | SVG 出力 | 方針 |
|---|---|---|---|
| 瞳孔の輪郭の柔らかさ (`PupilSoftness`) | 瞳孔の色で半透明の太い線を描く | **何も出していない**（設定が効かない） | SVG に入れる。まず WPF と同じ太い線で揃え、後で `feGaussianBlur` による本物のぼかしに置き換える |
| 外輪の境界の柔らかさ (`LimbalRingSoftness`) | 内側にぼかし用の線を足す | **何も出していない** | 同上 |
| 下部の反射光 | 透明な黒 → 色（途中が暗く濁る） | 透明な同じ色 → 色 | SVG の見た目（濁らない）を採る |
| 上部の影の濃さ | 不透明度 160/255 ≒ 0.63 | 0.65 | どちらかに揃える（差はわずか） |

**手順 2 で見つかった違い**（上の表に加えて）
| 項目 | WPF | SVG 出力 | 方針 |
|---|---|---|---|
| レンズ中心の屈折光 (`LensRefractionGlow`) | 色 → 透明な黒 | **何も出していない** | SVG に入れる。フェードは同じ色の透明へ（下部の反射光と同じ） |
| フレネルリングの点線 | 線幅 0.8 倍、線幅に比例した 4:3 の細かい点線（四角い端） | 線幅そのまま、1.5mm / 1.0mm の長い破線 | WPF の見た目を採る（10mm の目に 1.5mm の破線は粗すぎる） |
| 縦長・横長の虹彩の下地グラデーション | 長いほうに縦横比ぶん余分に広がる | 虹彩と同じ形の楕円（箱の 55%） | SVG の見た目を採る |

**結果**: 瞳孔・外輪の柔らかさは、まず WPF と同じ「太く薄い線」で SVG に入れた（本物のぼかしは手順 7）。それぞれ表の方針どおりに、SVG か WPF の片方を直した。

**確かめ方**: 試作の比較ツールを一時的なテストにする。WPF と resvg の平均の差を、全プリセットで 1.5 以下（アンチエイリアスの範囲）にする。→ `SvgWpfParityTests`（全 25 プリセットの左右と、縦長・傾き・オッドアイ・柔らかさ最大・全種類のグラデーションを使う設定。600 DPI）。手直し前は 3〜5、手直し後は 1.1 以下（ラメが密集した「星屑」が最大）。5 章の手順 2 が終わったら、このテストは WPF の実装と一緒に消す。

## 5. 進め方

各手順は、それぞれ 1 つの PR にする。

1. **resvg の組み込み**: `build-resvg.yml`、`third_party/resvg`、`ResvgRasterizer`、`NOTICE.md`。テスト: 単純な SVG を描くと、指定した大きさで期待した色になる。プレビューの大きさ（片目 136 DIP × 画面倍率）で何ミリ秒かかるかもここで測る（6 章のリスク）。
2. **見た目を揃える**: 4 章。`SvgExporter` だけを直し、WPF と resvg の比較テストで確かめる。
3. **出力を切り替える**（済み）: PNG と PDF を `ResvgRasterizer` で描く。`RasterExporter.RenderSingleToBitmap` と `RenderPairToBitmap` の中身を差し替えるだけで、呼び出し側（`PdfExporter`、`DesignFileWorkflow`）は変えない。PDF に埋め込む画像の形式（JPEG 98 のままにするか、ノイズの多い表現のために Flate 圧縮にするか）は、ファイルの大きさを見て決める。
   - 結果: `SvgExporter` に余白とカットライン・センターマークを別々に指定できる版を足し、`RasterExporter` はその SVG を `ResvgRasterizer.RenderAtDpi`（実寸どおりに左上から描く）で画像にする。書き出す SVG の中身は変わらない。
   - PDF の目の画像は、切り上げたピクセル数どおりの大きさで置く（これまでは 1 ピクセル未満だけ引き伸ばしていた）。
   - 埋め込みは JPEG 98 のまま。ノイズの多い表現（手順 7）を入れるときに、Flate 圧縮と大きさを比べて決め直す。
   - 起動時に resvg を 1 回呼んで確かめる。リリースと同じ単一 exe で読み込めること、DLL がないと警告が出ることを確認した。
   - 印刷補助マークは SVG の見た目（0.15mm の灰色の 2mm 破線、十字）にそろえた。画面のプレビューは手順 4 までは WPF の見た目（細い点線・中心の白丸）のまま。
4. **プレビューを切り替える**（`IrisPreviewControl`）:
   - ペア表示: 今の倍率・画面の DPI でペアの SVG を描いた画像を 1 枚持つ。パン（移動）だけなら描き直さない。
   - 倍率を変えたとき: すぐに今の画像を拡大縮小して表示し、描き直しが終わったら差し替える。
   - 設定を変えたとき: 裏のスレッドで描く。描いている途中に次の変更が来たら、最新の状態だけを描く（ブラウザ版と同じ考え方）。
   - A4 シート: 今の「同じデザインは 1 回だけ作って使い回す」キャッシュを、画像のキャッシュ（デザイン・左右・倍率で引く）に置き換える。用紙・余白線・文字は WPF のまま描く。
5. **WPF の描画を削除する**: `WpfIrisRenderer` を消す。ほかの場所で使っているものは移す。プレビュー倍率の定数は `IrisPreviewControl` へ、色見本の円周グラデ（`CreateConicBrush`、`ColorPickerBox` が使用）は `WpfGeometry` へ。`WpfIrisRenderer` を使っているテスト（`ColorGradientTests`、`CompareSlotTests`、`GemNebulaPresetTests`、`IrisGeneratorTests`、`SampleLooksTests`、`ShapeOutlineTests`）は、SVG の内容を確かめるか resvg の画素を確かめる形に書き直す。
6. **仕様書を更新する**: `SPECIFICATION.md` の 2.3（構成）、7.1.1（描画実装）、16（プレビュー）、17（SVG 出力）、19（ラスタライズ）。
7. **新しい表現を足す**（ここからが本来の目的）。それぞれ 1 つのパラメータとして足す。
   - 放射グラデの焦点（光の入る向き）
   - `mask` による放射ライン・星雲・ラメのフェード
   - 本物のぼかし（瞳孔・外輪の柔らかさ、ラメの光のにじみ）
   - `feTurbulence` による繊維ノイズ・まだら模様（`feDisplacementMap` で放射ラインを揺らすことも）
   - `screen` / `overlay` / `color-dodge` のブレンドモードを、オーロラ・ハイライト・ラメに
   - 星雲を `feTurbulence` で作り直す（PNG の埋め込みと C# のノイズ計算が要らなくなり、SVG は片目あたり 100〜200KB 小さくなる。ブラウザ版も速くなる）

## 6. リスクと対策

| リスク | 対策 |
|---|---|
| ドラッグ中のプレビューが遅い（フィルターは画素数に比例して重い） | 手順 1 で、プレビューの大きさで計測する。遅ければ、ドラッグ中だけ解像度を半分にし、手を離したら原寸で描き直す |
| ブラウザ版とデスクトップ版で見た目がわずかに違う（特に `feTurbulence`） | 雰囲気は同じなので受け入れる。印刷の基準はデスクトップ版（resvg）とする。仕様書に書いておく |
| resvg が対応していない SVG の機能を使ってしまう | 新しい表現を足すときは、resvg と Edge の両方で描いて比べるテストを一緒に足す（試作の比較ツールを流用） |
| ネイティブ DLL の管理 | バージョンを固定し、SHA-256 を記録する。更新はワークフローを再実行するだけ |
| 書き出した SVG を Illustrator で開くと、フィルターがラスター化される | 17 章に書いておく。困ったら、フィルターを省く「編集用」オプションを後で足す |

## 7. 対象外

- PDF をベクターで出力すること（今も画像の埋め込みなので変えない）
- ブラウザ版の描画方式（今も SVG をブラウザで描いているので変えない）
- 保存済みのデザインファイルを、新しい見た目に合わせて変換すること（互換は気にしない前提）
